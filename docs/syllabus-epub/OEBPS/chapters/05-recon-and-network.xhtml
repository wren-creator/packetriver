Session 5: Recon and the Network Lanes

Goal for this session: map the town by name, then work two attacks that are a different muscle from everything else in the book, layer 2 and lateral movement.

5.1 The name server

Every target answers to a business name. A CoreDNS container is the attacker box's only resolver, authoritative for packetriver.range, with the names as CNAMEs onto the container network so dig, nslookup, curl, and nmap water.packetriver.range all follow through.

  • The zone answers a transfer from anyone. recon.py dns (or a plain dig axfr) dumps every host in town, plus a stray TXT record for a box that was supposed to be decommissioned, with a maintenance token in it. Open AXFR is one of the oldest external-recon wins there is, and stale records for retired kit routinely outlive the kit. MITRE T1590.002. Fix: restrict transfers to known secondaries, split an internal view from an external one, and keep secrets out of DNS.
  • Reverse DNS. recon.py rev pulls a PTR for every box the name server knew at boot. Cross-check it against the forward zone.
  • The directory. /directory and /whois?q= on the map server list every official name and its hostname. A real internal corporate directory leaks exactly this.

5.2 The Diner's open Wi-Fi

Honest scope first: Docker has no radio, and shipping something that de-authenticates real access points would be irresponsible. This lane is a switched LAN taught as open 802.11. The lesson, unencrypted traffic on a shared medium is readable and MITM-able, is the same; the RF layer is a real wireless course, not this range.

The Diner runs a cleartext rewards portal and a toy POP3 server, and a scripted patron signs in and reads mail over the segment every few seconds. A switch will not flood their unicast to you, so the attack is an active ARP-spoof man-in-the-middle: get between the patron and the access point, forward, and read the traffic. The flag is sitting in the patron's inbox. wifi_sniff.py scripts arpspoof and tcpdump. It is loud on purpose: the access point watches its own ARP cache, catches the flipped MAC, and feeds the Alert meter; a sustained spoof crosses Level 1. MITRE T1557.002 (ARP cache poisoning), T1040 (network sniffing). Fix: WPA2-Enterprise or per-client isolation, and TLS on the portal and the mail so a MITM gets ciphertext.

5.3 The SOHO router pivot: residential to OT

A house on the edge of town runs a consumer router. The homeowner is a Packet River & Southern rail engineer who works from the couch. This is the remote-worker pivot that groups like Volt Typhoon actually run, and nothing else in the range covers it.

The router has WAN-side administration reachable from the town network, the admin login is still the shipped admin / admin, and its Diagnostics page will hand you a decoded capture of the home LAN, where the resident signs in to a rail crew portal over plain HTTP on a loop. Pull the capture, read the flag, and the credential in there is reused on the real rail maintenance console. Log in with it, read the rail flag, throw the switch. soho_pcap.py scripts the router side. MITRE T1078.001 (default accounts), T1040 (the capture-page abuse), T1078 again (the credential reuse into OT). Fix: disable WAN-side administration, force a change off the default at first login, put the crew portal behind TLS, and never reuse operator credentials between a web portal and a device console.

5.4 What you should notice

Recon by name changes how you think about the range. Instead of a list of ports on 127.0.0.1 you have an organisation: a water authority, a power company, a railroad, a bank, a row of shops. That is what a real target looks like, and the zone transfer that hands it all to you in one request is a real finding you will see on real engagements.
