Session 2: Main Street

Goal for this session: work eight storefronts, one bug class each, so no two teach the same thing. They are all vhosts on one shared PHP/Apache container, published on 127.0.0.1:8090 and reachable by name through the gateway (generalstore.packetriver.range and so on), each behind a login portal. The tool is whatever fits the bug. The map effect is always the storefront changing status.

2.2 Real-world parallels

None of these are exotic. The LIKE-clause concatenation is the shape behind countless breaches (CWE-89). Broken object-level authorization is OWASP API Security number one; the Panera Bread and USPS "Informed Visibility" leaks were mass IDOR. Exposed .git is a standing bug-bounty find (CWE-527). SSRF to something only the server can reach is Capital One, 2019 (CWE-918). Default credentials on a point-of-sale admin is Mirai's entire business model (CWE-1392).

2.3 MITRE ATT&CK

Almost everything here is T1190 (exploit public-facing application) into T1213 (data from information repositories). The barber's stored XSS is T1059.007. The default-cred tavern is T1078.001. The Bait & Tackle SSRF opens the door to T1046 (network service discovery) against the internal side.

2.5 The recon layer

The shops share one container, but the gateway hands each vhost a distinct Server and X-Powered-By header, so app-layer fingerprinting still tells them apart. That is deliberate. Real shared hosting looks exactly like this, and a good recon pass notices the difference between "Apache/2.4.58 (Ubuntu) with PHP/7.4.33" and "LiteSpeed, no PHP header" even when both answer on the same IP.
